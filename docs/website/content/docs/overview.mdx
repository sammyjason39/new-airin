Airin is an open-source platform for building teams of AI agents.

Every agent has a role. Together, they're your airin.

The easiest way to think about it:

- One Airin server can host many organizations
- Each organization can have many members
- Each organization can have many profiles
- Each profile is a bot with its own behavior, memory, and tool access

## Core mental model

If you are using Airin, most of the product can be understood through these four ideas.

### 1. Organization

An organization is the main boundary in Airin.

It keeps one team's data separate from another team's data, including:

- Members
- Profiles
- Sessions
- Tools
- Skills
- MCP servers
- Usage data
- Org memory — shared facts for the whole organization

### 2. Profile

A profile is an agent on your team — the bot users talk to.

Each new organization starts with a **Default Bot** and a **Airin**.
Additional profiles are created when you need another role or behavior.

Each profile has a role. It defines:

- The bot's identity
- The bot's instructions
- Which model it uses
- Which tools it may call
- Which knowledge base it can search

Profiles start with the standard builtin tools and default bundled skills. You
can assign more tools, MCP servers, and skills for each profile.

Org memory holds team-wide facts every profile shares; profile `MEMORY.md` holds per-bot continuity. See [Org memory](/org-memory) and [Profiles](/profiles#knowledge-base-and-memory).

### 3. Tool access

Profiles start with a safe baseline of builtin tools and bundled skills, but do
not automatically get every capability.

You choose which tools a profile can use, such as:

- Web search and web fetch
- File access and Word document generation (`write_docx`)
- Knowledge base search
- Email
- Skill creation
- Sub-agent delegation (`sub_agent`, opt-in)

Bundled skills extend profiles with system workflows such as memory writes (`update-profile-memory`), memory archives (`archive-profile-memory`), artifact design (`artifact-design`), slide decks (`slide-deck-design`), automations (`create-automation`), skill authoring (`manage-skills` — see [Self-improving skills](/self-improving-skills)), the coding agent (`coding-agent` skill), and interactive browsing (`agent-browser` skill). External SaaS apps connect through [Composio](/composio). See [Skills](/skills), [Coding agent](/coding-agent), [Agent browser](/agent-browser), and [Builtin tools](/builtin-tools).

This is how you keep one bot safe and narrow while another bot can be more capable.

### 4. Channels

The same Airin profile can be used from different places:

- Web dashboard
- CLI
- Telegram
- WhatsApp
- Discord
- Slack
- Microsoft Teams

## Simple and Advanced mode

The web dashboard has two modes. Switch in the user menu at the bottom of the sidebar.

| Mode | For | What you see |
|---|---|---|
| **Simple** | Business owners. New installs start here | Your team: each agent with its role under the name, your **Groups**, and **Marketplace**. Tool details stay folded. Opening chat brings back your last conversation with that agent |
| **Advanced** | Admins and operators | All profiles, settings, tools, MCP, skills, and token usage |

In Simple mode, select **New chat** to start a blank conversation.

## Agents that work together

You can get one answer from several agents in two ways:

- **Ask the orchestrator.** Jovan sends each part of your question to the right teammate, waits for their replies, and gives you one answer that says who supplied each fact. Every agent can do this with the `send_to_bot` tool. See [`send_to_bot`](/send-to-bot).
- **Open a group.** Several agents read one brief and answer in the same chat. See [Agent groups](/agent-groups).

## How to run Airin

Airin can run:

- As a [live demo](https://demo.getairin.cloud) — sign in with `demo@getairin.cloud` / `demo1234` to explore without installing
- On [managed hosting](https://getairin.cloud/) — sign up, create an instance, and open your dedicated URL (for example `acme.getairin.cloud`)
- Locally with Bun for development
- In Docker on your own infrastructure

See [Quickstart](/quickstart) for setup steps.

## Typical setup

Most deployments follow this pattern:

1. Create the first organization
2. Add members
3. Create one or more profiles
4. Assign tools to each profile
5. Upload knowledge base documents if needed
6. Let users chat with the right profile

## Who Airin is for

Airin is a good fit when you want:

- A team of AI agents, not a single general-purpose assistant
- Each agent with a distinct role, tools, and behavior
- Your own open-source agent platform — self-hosted or on [managed hosting](https://getairin.cloud/)
- Team or tenant separation across organizations
- Web and messaging channels on top of one backend

It is less about writing one prompt and more about assembling and operating your airin.
